Teaching Strategy (50-60 minutes)

Part 1: How Programmers Approach Big Problems (15 minutes)

🎯 Opening Hook

"How do you eat an elephant?"

One bite at a time!

This is exactly how programmers tackle complex problems. Today we'll learn the two main techniques: Decomposition and Abstraction.

🔹 Decomposition - Breaking Problems Down

What is Decomposition?

Definition: Breaking a complex problem down into smaller, more manageable sub-problems that are easier to solve.

Why decomposition?
  • Makes complex problems less overwhelming
  • Each smaller problem can be solved separately
  • Different people can work on different parts
  • Easier to test individual pieces
  • Can reuse solutions to sub-problems elsewhere
📚 Real-Life Example 1: Planning a Birthday Party

The Big Problem: Organize a birthday party for 20 friends

Without Decomposition: "I need to organize a party" — OVERWHELMING!

With Decomposition: Break it down into smaller tasks:

  1. Guest Management
    • Create guest list
    • Send invitations
    • Track RSVPs
  2. Venue & Decorations
    • Choose location
    • Buy decorations
    • Set up on the day
  3. Food & Drinks
    • Plan menu
    • Shop for ingredients
    • Prepare food
  4. Entertainment
    • Create playlist
    • Plan games/activities
    • Organize equipment

Key Insight: Each sub-problem is much easier to tackle than the whole party! You're already using decomposition in everyday life without realizing it.

🔸 Abstraction - Removing Unnecessary Detail

What is Abstraction?

Definition: Removing unnecessary details and focusing only on what's important for solving the problem.

Why abstraction?
  • Simplifies the problem by hiding complexity
  • Helps you focus on what matters
  • Makes problems easier to understand
  • Reduces information overload
🚗 Real-Life Example 2: Driving a Car

The Problem: Travel from home to a friend's house in a car

Without Abstraction - Engineering View:

  • Fuel injection timing sequences
  • Transmission gear ratios
  • Engine combustion cycles (thousands per minute!)
  • Brake hydraulic pressure calculations
  • Electronic stability control algorithms
  • Thousands of sensors and processors working together
  • Result: You'd need an engineering degree just to drive to the shops!

With Abstraction - Driving Interface:

  • Shows ONLY: Steering wheel, pedals (gas/brake), gear stick, speedometer
  • Hides: All the complex mechanics and electronics
  • Simple controls: Turn wheel → car turns, Press pedal → car goes faster
  • Result: Anyone can learn to drive without understanding how engines work!

Key Insight: The driving controls abstract away all the engine complexity. You don't need to know about fuel injection or transmission ratios to drive - you just use the simple interface (wheel and pedals). The unnecessary engineering details are hidden so you can focus on what matters: steering and speed!

🎮 Interactive Example: Walk Through Together (5-7 minutes)

Problem: Create a Simple Video Game

Task for Nathaniel: "You need to create a basic 2D platform game where a character jumps between platforms and collects coins. How would you break this down?"

🎤 Guide Nathaniel with prompting questions:
  1. "What are the main things this game needs to do?"
    Expected answers: Display graphics, move character, detect collisions, track score, etc.
  2. "Can we break those down even further?"
    Lead him to identify sub-problems within each main component
  3. "What details don't we need to worry about right now?"
    Help him identify what to abstract away: e.g., exact character appearance, sound effects, background music
✅ Example Decomposition (reveal after Nathaniel's attempt):
  1. Character Control
    • Move left/right with arrow keys
    • Jump when spacebar pressed
    • Apply gravity to bring character down
  2. Platform System
    • Draw platforms at specific positions
    • Detect when character lands on platform
    • Stop character falling through platforms
  3. Coin Collection
    • Place coins on platforms
    • Detect when character touches coin
    • Remove collected coin
    • Add to score
  4. Display & Interface
    • Draw game window
    • Display score counter
    • Show game over screen
✅ Example Abstraction (reveal after Nathaniel's attempt):

Details we DON'T need to worry about initially:

  • ❌ Detailed character animation (sprite sheets, walking frames)
  • ❌ Background scenery (clouds, trees, mountains)
  • ❌ Sound effects and music
  • ❌ Multiple levels
  • ❌ Enemy characters
  • ❌ Power-ups or special abilities
  • ✅ Focus on: Basic movement, platform collision, coin collection

Key Message: Start simple, add detail later!

Part 2: Introduction to Flowcharts (10 minutes)

🎯 What is a Flowchart?

Definition: A visual diagram that shows the steps of an algorithm using standardized shapes and arrows.

Why use flowcharts? They're visual representations that show the flow of logic through a program — perfect for visual learners like Nathaniel!

📐 Flowchart Shapes - The Building Blocks

Every shape has a specific meaning:

START / END
Oval / Rounded Rectangle

Purpose: Terminator

Used for: START and END of program

Examples: "START", "END", "STOP"

PROCESS
Rectangle

Purpose: Process / Action

Used for: Instructions, calculations, operations

Examples: "x = x + 1", "Calculate total", "Set count to 0"

INPUT/OUTPUT
Parallelogram

Purpose: Input / Output

Used for: Getting input from user or displaying output

Examples: "INPUT age", "OUTPUT total", "PRINT name"

DECISION
Diamond

Purpose: Decision / Condition

Used for: Yes/no questions, conditions

Examples: "age ≥ 18?", "x > 10?", "is_valid?"

Note: Always has 2 paths: YES/TRUE and NO/FALSE

🎨 Drawing Flowcharts on Whiteboard:
  • Arrows: Show the flow/direction of the program
  • Flow direction: Usually top-to-bottom or left-to-right
  • Label arrows from diamonds: Mark which path is "YES" and which is "NO"
  • Keep it neat: Use ruler or straight lines where possible

Part 3: The Three Programming Constructs (25 minutes)

🎯 Quick Reminder: The Three Constructs

Nathaniel already knows these from previous lessons. Today we'll see them as flowcharts!

  • Sequence: Instructions executed one after another
  • Selection: Making decisions (IF statements)
  • Iteration: Repeating instructions (loops)

1️⃣ Sequence - One Step After Another

What is Sequence?

Instructions that run in order, one after the other, from top to bottom.

Pseudocode:
START name = "Nathaniel" age = 14 birth_year = 2026 - age OUTPUT "Name: " + name OUTPUT "Born in: " + birth_year END
Flowchart:
    ╭─────────╮
    │  START  │
    ╰────┬────╯
         │
         ▼
    ┌──────────────────┐
    │ name = "Nathaniel"│
    └────────┬─────────┘
             │
             ▼
    ┌──────────────┐
    │   age = 14   │
    └──────┬───────┘
           │
           ▼
    ┌──────────────────────┐
    │ birth_year = 2026-age│
    └──────────┬───────────┘
               │
               ▼
    ╱──────────────────────╲
   ╱ OUTPUT "Name: " + name╲
   ╲──────────┬─────────────╱
              │
              ▼
    ╱────────────────────────╲
   ╱ OUTPUT "Born in: " +    ╲

                  │
                  ▼
             ╭────────╮
             │  END   │
             ╰────────╯
💡 Teaching Point: Notice how the flowchart flows straight down? That's sequence — no branching, no loops, just one step after another.

2️⃣ Selection - Making Decisions (IF statements)

What is Selection?

The program makes a decision and takes different paths based on a condition.

Pseudocode:
START INPUT age IF age ≥ 18 THEN OUTPUT "You can vote" ELSE OUTPUT "Too young to vote" ENDIF END
Flowchart:
      ╭─────────╮
      │  START  │
      ╰────┬────╯
           │
           ▼
      ╱──────────╲
     ╱ INPUT age  ╲
     ╲──────┬─────╱
            │
            ▼
         ╱────╲
        ╱      ╲
       ╱ age ≥  ╲   YES
      ╱   18?    ╲────────────┐
      ╲          ╱             │
       ╲        ╱              ▼
        ╲──┬───╱      ╱──────────────────╲
           │         ╱ OUTPUT "You can    ╲

           │                     │

   ╱ OUTPUT "Too     ╲           │
   ╲ young to vote"   ╱          │
    ╲────────┬────────╱           │

                      │
                      ▼
                 ╭────────╮
                 │  END   │
                 ╰────────╯
💡 Teaching Point: See how the diamond creates TWO paths? One for YES, one for NO. They join back together before the END. This is selection!

3️⃣ Iteration - Repeating (Loops)

What is Iteration?

Repeating a set of instructions multiple times. Notice the arrow that loops back!

Pseudocode (FOR loop):
START FOR count = 1 TO 5 OUTPUT count ENDFOR OUTPUT "Blast off!" END
Flowchart:
      ╭─────────╮
      │  START  │
      ╰────┬────╯
           │
           ▼
    ┌──────────────┐
    │ count = 1    │
    └──────┬───────┘
           │
      ┌────▼────┐
      │         │
      ▼         │
   ╱────╲       │
  ╱      ╲      │
 ╱ count  ╲ NO  │
╱  ≤ 5?   ╲────┼──────┐
╲         ╱     │      │
 ╲       ╱      │      │
  ╲─┬───╱       │      │
    │YES        │      │
    ▼           │      │
╱────────────╲  │      │
╲OUTPUT count╱  │      │
 ╲────┬──────╱  │      │
      │         │      │
      ▼         │      │
┌──────────────┐│      │
│count = count+1││      │
└──────┬───────┘│      │
       │        │      │
       └────────┘      │
                       │
                       ▼
            ╱────────────────────╲
           ╱ OUTPUT "Blast off!" ╲
           ╲──────────┬───────────╱
                      │
                      ▼
                 ╭────────╮
                 │  END   │
                 ╰────────╯
💡 Teaching Point: See the arrow that goes BACK UP? That's the loop! The program keeps going around until the condition becomes FALSE, then it exits the loop and continues.
Alternative: WHILE Loop

Same concept, different syntax. Condition is checked BEFORE executing the loop body.

Pseudocode (WHILE loop):
START count = 1 WHILE count ≤ 5 OUTPUT count count = count + 1 ENDWHILE OUTPUT "Blast off!" END
Note:

Flowchart looks very similar to FOR loop! The key difference:

  • FOR: Number of iterations is known
  • WHILE: Repeats as long as condition is true

In flowchart form, both show the same pattern: decision diamond with a loop-back arrow.

Summary and Key Points (5 minutes)

🎯 Essential Takeaways

  • Decomposition: Break big problems into smaller, manageable sub-problems
  • Abstraction: Remove unnecessary detail to focus on what matters
  • Flowcharts: Visual way to represent algorithms using standard shapes
  • Flowchart shapes:
    • Oval = START/END
    • Rectangle = Process/instruction
    • Parallelogram = Input/Output
    • Diamond = Decision (splits into YES/NO paths)
  • Three constructs in flowcharts:
    • Sequence = Straight line down
    • Selection = Diamond with two branches
    • Iteration = Arrow looping back up
